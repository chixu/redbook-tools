# 设计准则

## 目标

这些项目是日常使用的业务工具。优先让用户看清当前状态、找到下一步操作，并确认操作结果。各项目可以有自己的布局与主题，公共样式提供默认基础。

## 默认视觉变量

具体值以 `../styles/tokens.css` 为准，当前默认主题沿用库存工具：

| 变量 | 用途 |
| --- | --- |
| `--ink` | 主要文字 |
| `--muted` | 次要说明 |
| `--surface` | 页面背景 |
| `--panel` | 内容面板背景 |
| `--line` | 边框与分隔线 |
| `--spruce` | 主操作与强调文字 |
| `--mint` | 正向状态的浅色背景 |
| `--signal` | 异常、风险提示 |
| `--amber` | 需要注意的信息 |
| `--rail` | 深色辅助背景 |
| `--shadow` | 面板阴影 |

新增样式优先使用已有变量。项目可在自己的 `:root` 中覆盖主题；覆盖时同时检查文字和背景组合的可读性。共享变量更名时同步更新所有引用。

## 排版和布局

- 默认使用公共基础样式中的中英文字体栈，不强制加载远程字体。
- 页面标题、区块标题、正文和辅助说明保持清楚的层级；长文本保留足够行高。
- 先按业务信息组织页面，再选择表格、列表或面板。编号只用于真实的顺序。
- 同一页面的间距、圆角和控件尺寸保持一致，避免无目的的装饰。
- 窄屏允许导航换行、表单堆叠；数据表格确实需要时使用局部横向滚动，避免整页溢出。

## 交互和文案

- 按钮名称描述操作，例如“确认到货”；同一操作在按钮、反馈和记录中使用一致名称。
- 区分正常、悬停、键盘焦点、禁用和处理中状态。操作进行时避免重复提交。
- 使用语义化链接、按钮和表单标签；保留可见的键盘焦点。
- 状态同时用文字表达，不只依赖颜色。空状态说明下一步，错误提示说明原因和恢复方法。
- 常用触控操作尽量提供至少 44px 的点击区域。
- 动画服务于状态反馈；遵守 `prefers-reduced-motion`，避免不必要的持续运动。

## 交付检查

- 检查桌面和窄屏布局、长标题、空数据、错误和加载状态。
- 用键盘访问主要操作，确认焦点可见且不会被容器裁切。
- 公共样式变更检查所有已接入项目；新增主题检查文字对比和状态辨识度。
