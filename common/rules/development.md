# 开发约定

## 项目边界

- 各 Web 项目独立维护路由、业务组件、数据、环境变量和构建目录。
- 项目之间不直接导入对方的文件。需要复用的代码放入 `common/`，由项目引用。
- `common/` 不导入具体项目的代码，不读取某个项目的数据，不内置项目的环境变量或业务常量。
- 公共逻辑需要业务差异时，通过参数或组件属性传入。

## 依赖和配置

- 依赖统一在根目录 `package.json` 和锁文件中维护，在根目录执行安装命令。
- 项目继承根目录 Next.js 和 TypeScript 配置，差异在项目配置中明确覆盖。
- 项目内的 `@/*` 指向该项目；引用 `common/` 使用相对路径。
- 共享 React 组件默认保持服务端可用，需要状态、事件或浏览器 API 时再添加 `"use client"`。
- 服务端文件读写代码不要混入浏览器可引用的公共入口。

## 样式和变更验证

- 公共 CSS 按 `tokens → base → 项目样式` 的顺序加载，每个项目在根布局中接入一次。
- 项目专用样式留在项目内；新增共享组件优先使用 CSS Modules 避免全局类名冲突。
- 修改公共文件前检查引用它的项目，兼容已有用法；需要改变默认外观时说明影响。
- 修改共享代码或样式后，对受影响项目执行 `npm run typecheck -- <项目>` 和 `npm run build -- <项目>`。
- 视觉变化还应检查桌面、窄屏和键盘操作。单纯抽取样式应保持原有声明和加载顺序。
